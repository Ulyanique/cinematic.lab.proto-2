# Анализ проекта и разбор «камера уходит в черноту»

Дата: 16.11.2026 · ветка `arena/3d7f13d3-cinematic-lab-proto-2` · база `8ea5ff1`

Проект — кинематографическое WebGL-интро (three.js + собственный композер пост-обработки), где вся композиция
описывается схемой `src/intro/config.ts` и редактируется из UI. Внутри: собственный экструдер полигонов
(`extrude.ts` + `polyfix.ts`), генерация 3D-букв через `opentype.js`, покадровый экспорт видео через WebCodecs
(`mediabunny`), сборка в один HTML.

---

## 1. Почему кадр уходил в черноту

Проблема воспроизведена в портативном Chromium (`@sparticuz/chromium` + SwiftShader) замером средней
яркости кадра на каждом кадре: `npm run probe`. До правок картина была такая (зацикленное превью, 3 круга):

```
окна «чёрноты»:  0…0.54 с (7 кадров)  0…0.47 с (7 кадров)  0…0.49 с (7 кадров)
```

То есть **на каждом стыке кругов ~0.5 с абсолютно чёрного экрана**. Причина — не камера, а пролог ролика,
сложенный из трёх накладывающихся эффектов. Камера просто в этот момент ещё вне света, поэтому виноватой
выглядит она.

### Три причины (все подтверждены трассировкой uniform'ов)

| # | Механизм | Что было | Эффект |
|---|---|---|---|
| 1 | `uFade` (глобальное затемнение) | стартовал на **0.95 с** и доходил до 1 только к 2.2 с | первые ~1 с кадр умножался на 0 |
| 2 | «щель» (`uOpen`) | маска `1 - smoothstep(open-0.0016, open+0.0016, dy)` | при `uOpen < 0.002` обрезка шла по ~1.6 px UV — в кадре оставалась полоска, остальное чёрное (видно на скриншоте раннего пролога) |
| 3 | линия-зажигание + искра | старт на **0.25 / 0.2 с** | до 0.25 с в кадре не было вообще ничего светящегося |

Плюс два усилителя, из-за которых провал выглядел «случайным» и именно как поведение камеры:

* **Зацикливание:** `play(0)` стартовал пролог заново на каждом круге → гарантированный чёрный «моргающий»
  стык каждые ~14 с. Если `loop` включён, это и есть «периодически».
* **Скачок времени в фоновой вкладке:** время считается от `performance.now()`, а `requestAnimationFrame`
  в скрытой вкладке не тикает. Возврат в вкладку давал скачок `t` сразу на десятки секунд — ролик
  «телепортировался» в финал или снова в чёрный пролог. Это второй по частоте сценарий «само ушло в черноту».

### Что исправлено

* Пролог начинается сразу: зажигание сдвинуто в минус (`seg(t, -0.35, 1.55)`), искра горит на входе,
  `uFade` идёт от `0.3 → 1` за 1 с. Первый кадр уже содержит светящуюся искру и линию.
* «Щель» перестала быть маской, выжигающей кадр: добавлен `uSlitMix`, при тонкой щели маска плавно
  заменяется мягким затемнением (пол 22 %), кромка считается относительно `uOpen`, а не фиксированных 1.6 px.
* Стык кругов: в превью с `loop` ролик гаснет до 12 % (не в ноль) и новый круг входит за 0.4 с.
  В **экспорте** уход в чёрный остался честным (`fadeOut` → 0), как и было задумано.
* Фоновая вкладка: `visibilitychange` переякоривает таймлайн, скачков времени больше нет.
* `applySize` стал идемпотентным: раньше **каждое** изменение конфига (любой тик ползунка!) вызывало
  `composer.setSize()` → переаллокацию HDR-таргетов MSAA ×4 и 5 мипов bloom. Замер: 40 изменений конфига → 40
  applySize и 80 `renderTarget.setSize`. На слабом GPU это видимые провалы. Теперь — ранний выход при том же размере.
* `setClearColor(0x050403)` вместо чистого чёрного + `try/catch` вокруг `composer.render()`: единичный сбой
  прохода больше не оставляет «вечно чёрный» кадр, а сообщает об ошибке через `onWarn`.

### Проверка после правок

```
$ npm run build && npm run probe            # проигрывание, зацикливание
# кадров=84 чёрных=0
OK: чёрных кадров нет (84 замеров)

$ MODE=freeze TIMES=13.5,13.7,13.8,13.9,14.0,0.05,0.3,1,1.5,2,4.5,8,12 npm run probe
13.90 0.0312 ...   # стык кругов: тёмное янтарное, не ноль
OK: чёрных кадров нет (13 замеров)
```

`tools/probe.mjs` возвращает код 1 при чёрном кадре — годится как регрессионный тест.

Остаётся честно назвать то, что я **не** менял: в самом кадре удара (4.4–4.5 с) есть задуманный «замах» —
кадр темнеет на ~30 % (`dip`), и финальный кадр при `t = 0` в **экспорте** тоже начинается с затемнения.
Это художественная часть раскадровки, а не дефект.

## 2. Что ещё стоит улучшить

### Архитектура и надёжность

1. **`// @ts-nocheck` в 6 из 12 модулей** (`Intro.ts`, `gold.ts`, `title.ts`, `extrude.ts`, `polyfix.ts`,
   `streak.ts`). `tsconfig` включает `strict`, но именно в самых сложных файлах проверки выключены — отсюда
   «тихие» баги вроде `fillRule` в `logo.ts`. Минимальный шаг: включить проверку хотя бы для `Intro.ts`
   с `any`-полями движка, затем убирать `any` постепенно. Это самая большая инвестиция в качество.
2. **`Intro.ts` — 1500 строк и один класс на всё** (рендер, таймлайн, экспорт, текстуры, эффекты).
   Естественное разделение: `Timeline` (чистая функция `design → uniforms`), `CameraRig`, `Post`,
   `TextLayer`, `Exporter`. Плюс `Intro.ts` можно тестировать без GPU, если вынести расчёт кадра
   в чистую функцию — тогда `probe` заменится юнит-тестами на таймлайн.
3. **Нет тестов.** Есть скрипты-снимки (`frames.mjs`) и теперь `probe.mjs`, но ни одного автотеста.
   Что стоит покрыть без браузера: `warp()`/`totalDuration()` (границы, `hold`, `speed`), `sanitizeConfig`
   (мусор в JSON, переполнение чисел, дубликаты в `order`), `EASE`/`logoXf`/`letterXf` (0→0, 1→1, монотонность).
   Для полигонов уже есть браузерный GEO-режим — его стоит вызывать в CI.
4. **`preserveDrawingBuffer: true`** включён всегда. Он нужен только для `CanvasSource` при экспорте,
   а в превью стоит лишних кадров памяти и просадки. Лучше включать на время записи
   (пересоздавать рендерер нельзя, но можно `gl.preserveDrawingBuffer` через отдельный контекст экспорта).
5. **Экспорт блокирует UI-поток.** `record()` честно уступает на `setTimeout(0)` каждые 3 кадра и рисует
   прогресс, но рендер 4K на слабой машине всё равно «замораживает» панели. Кандидат на
   `OffscreenCanvas` + `Worker` (рендер в воркере без DOM) — большой выигрыш на длинных 60 fps-экспортах.
6. **Экспорт всегда 16:9.** Соотношение жёстко зашито (`EH = EW*9/16`), хотя CSS-вёрстка поддерживает
   произвольное. Стоит добавить выбор 1:1 / 4:5 / 9:16 для соцсетей — это дешёвая фича с высокой ценностью.
7. **`m`/`8`-лимиты и магия чисел.** В `gold.ts`, `Intro.ts` десятки «подобранных на глаз» констант
   (4.5, 0.62, 2.9 …). Часть уже в конфиге; остальные стоит свести в `timing.ts`/`palette.ts`, иначе
   любая правка таймлайна требует чтения всего файла.
8. **Доступность UI.** Панели — `div`-ы с `role`/`aria` местами; нет управления ползунками с клавиатуры
   по шагам (только нативный range), таймлайн `role="slider"` не обновляет `aria-valuenow` при проигрывании
   и не реагирует на стрелки. Скринридер не узнает о `progress` экспорта (есть `role=status`, но текст
   меняется не в live-регионе). Быстрые победы: `aria-valuenow`, `aria-valuetext`, горячие клавиши `←/→`
   для перемотки и `накглавные` подсказки.
9. **i18n.** Интерфейс и комментарии русские, `lang="en"` в `index.html` (ошибка), строки захардкожены.
   Если публиковать шире — вынести тексты в словарь и выставить `lang="ru"`.
10. **Проброс ошибок SVG.** Невалидный SVG даёт `onWarn`, но пользователь видит только строку в панели
    настроек. Стоит показывать бейдж на слое и подсвечивать поле.

### Производительность

11. **`warmUp()` рисует 7 кадров в `composer`** на старте — это правильно, но суммарно 7 × (bloom + streak +
    финальный проход) на 320×180. Можно один раз прогнать `renderer.compile` (уже есть) и 1–2 кадра,
    доверив остальное `KHR_parallel_shader_compile`. Мелочь, но ускоряет первый показ.
12. **`adaptQuality`** понижает до 1280/960 по среднему кадру, но никогда не поднимает обратно и не учитывает
    тип GPU. Стоит добавить гистерезис вверх и учесть `renderer.capabilities` (например, не опускать на дискретной карте).
13. **Streak-пасс** всегда рендерит `comp`-квад даже при `strength = 0` (ветка «пропустить bright/blur»), но
    всё равно делает полноэкранный проход. При `strength < 0.002` можно ставить `pass.enabled = false`.
14. **Текстуры `starTex`/`flareTex`/`glowTex` создаются через `ImageData` попиксельно** в JS при каждом
    `setupFX`/`setupLogo` (рестарт конфига). Их стоит сделать один раз и кешировать по модулю (как `_glow`).
15. **`MeshSurfaceSampler` для роя на 18 000 точек** пересобирается при любом изменении `size/depth/bevel`.
    Это `useMemo`-кандидат: кешировать выборку по «сигнатуре геометрии», как уже сделано для шрифтов.

### Продукт / UX

16. **Нет пресетов «под площадку»**: 9:16 сторис, 1:1 квадрат с упрощённой композицией (меньше слоёв) —
    сейчас все пресеты 16:9.
17. **Нет предпросмотра «только текст»/«только эмблема»** — карточки слоёв не дают миниатюр.
18. **`__applyConfig` в `window`** — удобно для тестов, но в проде это открытая точка изменения состояния.
    Стоит спрятать за `import.meta.env.DEV` (в `tools/frames.mjs` уже используется — оставить только в dev-сборке).
19. **`localStorage` без версии.** `STORE_KEY` содержит `v1`, но `sanitizeConfig` не мигрирует старые
    схемы. При добавлении полей старые сохранения просто получат дефолты — это ок, но при *удалении*
    поля оно останется в JSON. Стоит очищать неизвестные ключи при сохранении.
